# ENHSP: command-line guide

ENHSP is the Expressive Numeric Heuristic Search Planner built on JPDDLPLUS.
It accepts a PDDL domain and problem and searches for a plan. Classical,
numeric and discretised PDDL+ models are supported; full ADL support is partial.

For the library overview and repository layout, see [README.md](README.md).

## Build and help

Use JDK 16 or newer and Bash. Dependencies are in `lib/runtime/`;
there is no Maven/Ant setup step.

```bash
./compile.sh
java -jar enhsp25.jar -help
```

The build creates the CLI `enhsp25.jar` and GUI `enhsp25-gui.jar`. The help
generated by your built JAR is the complete option reference for that build.

## Solve a problem

```bash
java -jar enhsp25.jar \
  -o examples/pddl2_1/counters/domain.pddl \
  -f examples/pddl2_1/counters/instance_4.pddl \
  -planner sat-hmrp \
  -sp /tmp/counters.plan
```

`-o` selects the reusable domain; `-f` selects the objects, initial state,
goal and optional metric. The domain name in the problem must match the domain.

Useful presets include `sat-hmrp`, `sat-hadd`, `sat-aibr`, `opt-hmax`,
`opt-hrmax` and `opt-blind`. A preset configures the heuristic and search;
omit `-planner` when selecting them manually:

```bash
java -jar enhsp25.jar \
  -o examples/pddl2_1/counters/domain.pddl \
  -f examples/pddl2_1/counters/instance_4.pddl \
  -h blind -s wastar -wh 1
```

The available search strategies include `gbfs`, `wastar`, `lazygbfs`,
`lazywastar`, `ehs` and `ida`. Their behavior and supported combinations are
defined by the current implementation and CLI help.

## Common options

| Option | Meaning |
| --- | --- |
| `-planner NAME` | Apply a predefined configuration |
| `-h NAME`, `-s NAME` | Select a heuristic and search directly |
| `-wh WEIGHT` | Set the heuristic weight |
| `-timeout SECONDS` | Limit overall planning time |
| `-dl COST` | Set the path-cost bound; WAStar uses a strict bound |
| `-ties larger_g\|smaller_g\|arbitrary` | Select tie-breaking; default is `arbitrary` |
| `-sp FILE` | Save a returned plan |
| `-silent` | Suppress search progress output while retaining the result summary |
| `-print_actions` | Print grounded transitions |
| `-stopgro` | Stop after grounding |
| `-floor true\|false` | Select the numeric activation floor; default is `true` |
| `-crd none\|static\|online` | Select supported causal-reasoning decomposition |
| `-selzero base\|floor\|num\|numfract` | Select CPZeroCut zeroing mode; default is `floor` |
| `-aibr_debug` | Enable detailed AIBR diagnostics |

Advanced heuristic options are experimental. For example, CPZeroCut can be
selected with `-h cpzerocut`; non-`base` zeroing modes require `-floor true`.
Do not infer that every heuristic supports every PDDL construct or CLI option.

## PDDL+ processes and events

```bash
java -jar enhsp25.jar \
  -o examples/pddl+/car_non_linear/domain.pddl \
  -f examples/pddl+/car_non_linear/instances/instance_1_30.0_0.1_10.0.pddl \
  -planner sat-aibr -d 1
```

ENHSP discretises autonomous evolution. The combined `-d` option sets all
deltas. To choose different values, omit it and use `-dp` (planning), `-de`
(execution), `-dh` (heuristic) and `-dv` (validation). A plan is interpreted
under the selected discretisation, rather than as a guarantee for arbitrary
continuous evolution.

## Results and validation

`Plan-Length` and the returned action sequence identify a found plan; they
do not establish independent validation. Although `-ival` and `-inputplan`
appear in the CLI help, the current command-line planning path only parses
these fields and does not consume the supplied plan for validation. Do not
use them as evidence that an existing plan was checked.

A timeout, exhausted cost bound or missing plan does not by itself prove that
the original problem is unsolvable. Inspect the termination output and, for
PDDL+, retain the discretisation settings with the result.

## GUI and examples

```bash
java -jar enhsp25-gui.jar
```

Start with [the GUI examples](examples/gui/README.md), `examples/pddl2_1/`,
or `examples/pddl+/`. Docker recipes
are available through the root `Dockerfile` and `docker-builder/build.sh`.
They build the current local checkout, including uncommitted changes.

```bash
docker build -t enhsp25 .
docker run --rm enhsp25 -help
docker compose run --rm enhsp -help
```
